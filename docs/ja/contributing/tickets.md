# チケット

チケットの形式でコミュニティからのフィードバックと助けを得ることは、フォークをメンテナンスする上で
極めて重要です。チケットは GitHub の Issue です。フレームワークの問題は
[pieceofcake2/cakephp の Issues](https://github.com/pieceofcake2/cakephp/issues) に、
アプリケーションスケルトン、Bake、プラグインの問題はそれぞれの `pieceofcake2/*` リポジトリの
Issues に報告してください ([メンテナンスされているプラグイン](/ja/plugins/maintained-plugins) を参照)。
このドキュメントの問題は [pieceofcake2/docs](https://github.com/pieceofcake2/docs/issues) へ報告してください。

フォークの問題を cakephp/cakephp に報告しないでください。CakePHP 2.x は本家ではもうメンテナンスされていません。

## バグの報告

Issue を作成する前に確認すること、Issue に書く内容は、コントリビューションガイドの
[Reporting Issues](https://github.com/pieceofcake2/.github/blob/master/CONTRIBUTING.md#reporting-issues) (英語) で説明しています。
報告する前に [CakePHP 2.10 からの移行](/ja/appendices/migrating-from-cakephp-2-10) も
確認してください。見ている挙動が、フォークで意図的に行われた変更である場合があります。

<a id="reporting-security-issues"></a>

## セキュリティ問題の報告

セキュリティ問題は、公開の Issue、Pull Request、Discussion では報告しないでください。
Organization の [セキュリティポリシー](https://github.com/pieceofcake2/.github/blob/master/SECURITY.md) の説明に従い、GitHub の非公開の脆弱性報告
(private vulnerability reporting) を使って報告してください。
修正済みの脆弱性は [脆弱性への対応](/ja/security/fixes) にまとめています。
