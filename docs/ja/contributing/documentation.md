# ドキュメント

ドキュメントへの貢献の方法はシンプルです。
ファイルは <https://github.com/pieceofcake2/docs> の `2.x` ブランチにホストされています。
自由にリポジトリをフォークして、変更・改善・翻訳を追加し、Pull Request を作成してください。
またファイルをダウンロードせず、各ページの下部にある "Edit this page on GitHub" リンクから
GitHub のオンラインエディタを使って直接ドキュメントを編集することもできます。

ドキュメントは Markdown で書かれ、[VitePress](https://vitepress.dev) でビルドされます。
`2.x` ブランチにマージされた変更は、GitHub Actions によって自動的に
<https://pieceofcake2.github.io/docs/> にデプロイされます。

変更をローカルで確認するには、リポジトリのルートで開発サーバーを起動します。
`git`、`node`、`npm`、`rsync` が必要です。

``` bash
./bin/dev-server.sh
```

このスクリプトはサイトのテーマを取得してドキュメントをコピーし、
<http://localhost:5173> で VitePress を起動します。

## リポジトリの構成

- `docs/en/` に英語のページが、`docs/ja/` に日本語のページがあります。
  2 つのフォルダーの構造は同じで、`docs/en/foo/bar.md` の翻訳は `docs/ja/foo/bar.md` にあります。
- `toc_en.json` と `toc_ja.json` はそれぞれの言語のサイドバーを定義しています。
  ページを追加したときは、両方のファイルに追加してください。
- `config.js` には、ナビゲーションバーやバージョンバナーといったサイトの設定があります。

英語のページはサイトのルート (`/installation`) から、日本語のページは `/ja/`
(`/ja/installation`) から配信されます。

## 翻訳

ドキュメントは英語と日本語でメンテナンスしています。常に英語版を正となるバージョンと考えてください。
英語のページを変更したときは、できれば日本語のページも更新してください。
できない場合は、翻訳の更新が必要なことを Pull Request に書いておいてください。

### 翻訳者 tips

- 翻訳する言語のページで閲覧・編集してください。
  そうしないと、どこが既に翻訳されているかわからないでしょう。
- タイトルと内容を同時に翻訳してください。
- 修正を投稿する前に、英語版との比較を行うようにしてください。
  どこかを修正しても、以前の変更が統合されていなかったら、投稿したものが受け付けられないことがあります。
- ページ間のリンクがどちらの言語でも機能するように、ページの構成、コード例、アンカーは
  英語のページと同じにしてください。
- 既存の日本語のページと同じ用語を使ってください。
- 一部だけ翻訳して投稿しないでください。
- アクセント文字のために
  [HTML エンティティ](https://en.wikipedia.org/wiki/List_of_XML_and_HTML_character_entity_references)
  を使用しないでください。この本は UTF-8 を使っています。
- 元のコンテンツに不備がある場合は、まずそれを編集するようにしてください。

## ドキュメントのフォーマットガイド

ページは VitePress の拡張をいくつか加えた普通の Markdown です。一貫性を保つために、
ドキュメントに追加するときはここで説明するガイドラインに従い、既存のページも参考にしてください。

### 行の長さ

テキストの行は 80 桁程度で折り返してください。例外は長い URL、表、コードスニペットだけです。
日本語の文章では、句読点など切りのよいところで適度に改行してください。

### 見出し

各ページは 1 つの `#` 見出し (ページタイトル) で始めます。セクションには `##`、
サブセクションには `###`、その下には `####` を使います。見出しは 4 レベルより深くネストせず、
前後に空行を入れてください。

VitePress は見出しのテキストからアンカーを生成します。たとえば `## Running Tests` には
`#running-tests` というアンカーが付きます。日本語の見出しからは同じアンカーが生成されないので、
英語のページと同じアンカーが日本語のページにも必要な場合は、見出しの前に明示的に追加してください。

``` md
<a id="running-tests"></a>

## テストの実行
```

### インラインのマークアップ

- アスタリスク 1 つ `*text*` は強調 (イタリック) です。
- アスタリスク 2 つ `**text**` は強い強調 (太字) です。使いすぎないでください。
- バッククォート `` `text` `` はコードを表します。メソッドや関数の名前 (`()` を付けます)、
  クラス名、オプション名、テーブルのカラム、ファイル名やパスに使います。
  例えば `PagesController`、`find()`、`config/core.php` などです。

### リスト

順序なしリストは各項目を `-` と空白で始めます。番号付きリストは `1.`、`2.` のように書きます。
ネストしたリストや項目の継続行は、2 つの空白 (番号付きリストでは 3 つ) でインデントします。

``` md
- This is a bullet
- So is this. But this line
  has two lines.

1. First line
2. Second line
```

### リンク

外部のドキュメントへのリンクには、通常の Markdown の記法を使います。

``` md
[External Link](https://example.com)
```

ドキュメント内の他のページへのリンクでは、`.md` 拡張子を省略します。現在のページからの
相対パスか、言語のルートからの絶対パスを使えます。絶対パスは、英語のページでは `/` で、
日本語のページでは `/ja/` で始めます。

``` md
[Controllers](../controllers)
[Testing](/development/testing)
[テスト](/ja/development/testing)
```

セクションへリンクするには、見出しのアンカーを付けます。

``` md
[テストの実行](/ja/development/testing#running-tests)
```

### クラスとその内容の説明

クラスやメソッドのための特別なディレクティブはありません。ページでは、クラスとメソッドを
次の形式の行で示し、その後に説明を書きます。

``` md
`class` **Cache**

`static` Cache::**read**($key, $config = 'default')

`Cache::read()` は `$key` の下に保存されたキャッシュの値を読み込むのに使います...
```

本文中でクラスやメソッドに触れるときは、`Cache::read()` のようにバッククォートで囲みます。

### ソースコード

コード例は、ハイライトされるように言語名を付けたフェンス付きコードブロックで書きます。
PHP のコードには `php`、シェルのコマンドには `bash`、出力やハイライトしないものには
`text` を使います。

```` md
``` php
$cloud = Cache::read('cloud');
```
````

PHP のコード例は [コーディング規約](cakephp-coding-conventions) に従います。
読者の役に立つ場合は、`// src/Controller/PostsController.php` のように
モダンなアプリケーション構成でのファイル名をコメントでコード例の先頭に書いてください。

同じコマンドをツールごとに示すような選択肢は、`::: code-group` コンテナでまとめられます。

### 注意と警告

重要なヒント、特別な注意事項、潜在的な危険について読者に知らせたいことがよくあります。
次のアラートを使ってください。

``` md
> [!TIP]
> これはあなたが忘れているかもしれない便利な小技です。

> [!NOTE]
> ここに注意を払うべきです。

> [!WARNING]
> 危険かもしれません。
```

- TIP は、興味深い情報や重要な情報を記述したり、改めて示したりするために使います。
- NOTE は、特に重要な情報を記述するために使います。
- WARNING は、潜在的な障害やセキュリティに関する情報を記述するために使います。

アラートの内容は、適切な句読点を付けた完全な文で書いてください。

CakePHP 2 で機能が追加、変更、非推奨になったバージョンを示すには、
タイトル付きの `info` コンテナを使います。

``` md
::: info バージョン 2.6.3 で追加
このすばらしい機能はバージョン 2.6.3 で追加されました。
:::

::: info バージョン 2.6.3 で非推奨
この古い機能はバージョン 2.6.3 で非推奨になりました。
:::
```

`tip`、`warning`、`danger` のコンテナも同じようにタイトルを付けて使えます。

#### フォークでの変更点

Piece of Cake 2 フォークの動作が本家 CakePHP 2.10.24 と異なり、アプリケーションを移行する
読者が知っておくべき場合 (機能の削除、デフォルト値の変更、メソッドのシグネチャの変更など) は、
該当する本文の近くに `pieceofcake2` コンテナで短い注記を追加してください。

``` md
::: pieceofcake2
Xcache と Wincache のキャッシュエンジンは削除されました。
:::
```

デフォルトのタイトルは "Piece of Cake 2 fork" です。`::: pieceofcake2 キャッシュエンジン`
のようにコンテナ名の後に別のタイトルを指定することもできます。注記は 1〜3 文に収めてください。
現在のパスやコマンドなど、それ以外の内容はすべてページの本文に書きます。

#### サンプル

> [!TIP]
> これはあなたが忘れているかもしれない便利な小技です。

> [!NOTE]
> ここに注意を払うべきです。

> [!WARNING]
> 危険かもしれません。

::: info バージョン 2.6.3 で追加
このすばらしい機能はバージョン 2.6.3 で追加されました。
:::

::: pieceofcake2
Xcache と Wincache のキャッシュエンジンは削除されました。
:::

### 他のファイルの取り込み

ページには、HTML コメントの形で書く VitePress の `@include` ディレクティブを使って、
他の Markdown ファイルの一部を取り込めます。例えば、同じセクションを 2 つのページで
表示するために使われています。`docs/ja/core-libraries.md` に例があります。
ファイル名の後に `{28,97}` のように波括弧で行の範囲を書くと、その行だけを取り込みます。
他のファイルから取り込まれているファイルを編集した場合は、リポジトリ内で `@include` を検索し、
取り込む側の行の範囲が同じセクションを指しているか確認してください。
